# Проверка: тесты, смоук в браузере, снимки экранов, отладка

Источники: test/levels.test.js, test/game.test.js, test/progress.test.js, test/sprites.test.js, test/pwa.test.js, test/autopilot.js, test/browser.smoke.mjs, tools/verify.sh, tools/browser.mjs, tools/screens.mjs

## Что запускать
| Изменил | Команда | Время |
|---|---|---|
| логику (src/core), данные графики | `tools/verify.sh` | ~2 с |
| сцены, интерфейс, камеру, ввод, текстуры | `tools/verify.sh ui`, затем снимки `node tools/screens.mjs <пресет>` | ~45 с + ~3 с на снимок |
| только документы базы знаний | `python3 tools/kb.py check` | мгновенно |

`tools/verify.sh` печатает по одной строке на этап (`тесты: ok…`, `браузер: ok…`, `kb: ok`); подробности — только при ошибке.
Код возврата ≠ 0 при любой проблеме. Полный вывод тестов — `npm test` (нужен редко).

## Тесты в Node (`node --test test/`)
- test/levels.test.js — 210 уровней (70 индексов × 3 пропорции экрана): инварианты решаемости (см. levels.md), детерминизм, появление механик
  на уровнях-знакомствах, плавность кривой.
- test/game.test.js — автопилот проходит 120 уровней настоящей логикой; проверки пошагового управления, дверей, подсказок, жизней, звёзд.
  Несколько поражений автопилота на уровнях со сторожами — норма (порог — 15 %); **застревание — провал**.
- test/progress.test.js — сохранение, лучший результат, повреждённые данные, сброс.
- test/sprites.test.js — размеры и символы спрайтов; картинка лабиринта: стена ровно там, где нет прохода.
- test/pwa.test.js — sw.js кэширует все файлы игры; версия совпадает в src/config.js, sw.js и package.json.
- test/autopilot.js — общий «осторожный игрок» для Node и браузера: идёт к ближайшей цели, пережидает и обходит сторожей.

## Смоук в браузере — test/browser.smoke.mjs
Headless Chromium с WebGL (playwright-core, браузер из кэша Playwright). На телефоне 360×780 и ПК 1280×800: меню и смена героя, запуск игры
кнопкой, **реальные свайп, клавиша и тап** (каждый даёт ровно шаг), подсказка, пауза, включение экранных стрелок, победа → итоги → следующий
уровень, уровни-знакомства со всеми механиками (быстро, автопилотом), список уровней, поворот экрана, настройки и сброс прогресса.
Проверяет отсутствие ошибок на странице и что рендер — WebGL. Кнопки находит по имени (`name`), поэтому переименование подписи кнопки
надо отразить и в сценарии.

tools/browser.mjs — общий хелпер: статический сервер проекта на случайном порту, запуск браузера, функция `openGame` (ждёт `KLUBOK.ready`;
опция `save` кладёт сохранение `klubok.v2` до загрузки). Страница открывается с `?test` — service worker не регистрируется.

## Снимки экранов — tools/screens.mjs
`node tools/screens.mjs <пресет…>` — телефон 360×780 и ПК 1280×800, печатает пути к PNG (посмотреть через Read). Пресеты:
menu, levels, settings, intro, game, hint, pause, result, lose.
Ключи: `-m` только телефон, `-d` только ПК, `-t` ещё планшет 1024×768, `-l` ещё телефон лёжа 780×360 (сначала `-m` или `-d`, потом добавочные);
`--level N` (с нуля), `--hero id`, `--js "<код>" имя` — свой сценарий, `--hd` — снимок в пикселях устройства, `--out dir`.
Примеры: ночной уровень — `--level 30 game`; сторожа — `--level 22 game`; карточка первого уровня — `--level 0 intro`;
экранные стрелки — `--js "KLUBOK.progress.setSetting('dpad', true); KLUBOK.go('Game', { index: 22 })" dpad`.
Смотри не больше, чем нужно: 1–2 снимка затронутого экрана; широкий прогон по всем экранам — через агента `ui-check`.

## Отладка в браузере
`npm start` → http://localhost:8080. В консоли: `KLUBOK.go('Game', { index: 30 })`, `KLUBOK.game.scene.getScene('Game')` (поля `logic`, `level`),
`KLUBOK.progress.state`. Сброс сохранения: удалить ключ `klubok.v2` в localStorage или кнопкой в настройках.
Пройти уровень мгновенно: `KLUBOK.game.scene.getScene('Game').logic.win()`.

## Грабли
- Объект сцены Phaser переиспользуется между запусками: поле, которое выставляется только при условии (туман на ночном уровне), остаётся
  от прошлого уровня. Всё состояние уровня сбрасывать в `create()`. Именно такой баг поймал смоук.
- Операции со сценами (`scene.pause`, `resume`, `stop`, `launch`) выполняются в начале следующего кадра: сразу после вызова `isActive` ещё старый.
- Новые интерактивные объекты Phaser начинают принимать касания только со следующего кадра. Сценарий, который жмёт кнопку сразу после
  перестройки сцены (например, после смены героя), промахивается — поэтому `click` в смоуке ждёт 80 мс. Отладка одного размера:
  `SMOKE_ONLY=ПК node test/browser.smoke.mjs`.
- Playwright подставляет браузер из кэша `~/Library/Caches/ms-playwright`; если его нет — `npx playwright-core install chromium`.
- В скриптах `--js` нельзя писать комментарии `//` — код передаётся одной строкой.
- Правка генерации уровней меняет все сидированные уровни — перепроверь 210 уровней и автопилот.
- Service worker кэширует файлы по имени кэша с версией: новый файл в src → добавь в `ASSETS` в sw.js (тест напомнит), при выпуске — новая версия.
