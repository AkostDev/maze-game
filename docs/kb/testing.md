# Проверка: тесты, аудит вёрстки, скриншоты, отладка

Источники: tests/run.sh, tests/levels.test.js, tests/game.test.js, tests/ui.smoke.js, tests/dom-stub.js, tools/verify.sh, tools/screens.sh, tools/audit.js, tools/shot.sh

## Что запускать
| Изменил | Команда | Время |
|---|---|---|
| логику (maze, levels, game, progress, ai, story) | `tools/verify.sh` | ~4 с |
| интерфейс (ui.js, css, index.html, render, sprites) | `tools/verify.sh ui`, затем снимки `tools/screens.sh <пресет>` | ~25 с + ~4 с на снимок |
| только документы базы знаний | `python3 tools/kb.py check` | мгновенно |

`tools/verify.sh` печатает по одной строке на этап (`тесты: ok…`, `вёрстка: ok…`, `kb: ok`); подробности — только при ошибке. Код возврата ≠ 0 при любой проблеме.
Полный вывод тестов — `./tests/run.sh` (нужен редко).

## Тесты (tests/run.sh, движок — jsc из macOS, Node не нужен)
1. Синтаксис всех js/*.js и sw.js.
2. tests/levels.test.js — 812 уровней (4 возраста × 4 режима × 48 индексов × 3 пропорции + дни + сказки с ASCII): инварианты решаемости (см. levels.md).
3. tests/game.test.js — автопилот проходит 232 уровня настоящим движком (рендерер заменён заглушкой `fakeR`), плюс проверки пошагового режима
   и скольжения. Поражения автопилота у teen/pro со сторожами — норма (несколько штук); **`stuck` — провал**.
4. tests/ui.smoke.js — все экраны, модалки и игра во всех режимах на мини-DOM (tests/dom-stub.js): ловит исключения в ui.js / main.js.

Особенности jsc: вывод через `print`, нет DOM и таймеров — их даёт dom-stub (`__flushRaf(кадры, шаг)`, `__flushTimers(мс)`, у узлов есть
`dispatch(type, event)`). Заглушка минимальна: `querySelector` понимает только селекторы вида #id, .class, [attr] и имя тега; canvas-контекст — Proxy, глотающий
любые вызовы. Новый DOM/браузерный API в коде интерфейса → дополни заглушку. Списки файлов в tests/run.sh — вручную, в порядке index.html.

## Аудит вёрстки (tools/audit.js через tools/audit.sh)
Реальный WebKit на ширинах 320/360/390/430/768: онбординг, главная, уровни, сказка, рекорды, достижения, настройки, «кто играет», игра с HUD,
пауза, итоги. Ищет: «за экраном» и «не влезает» (ошибки), «многоточие» (текст обрезан с «…» — предупреждение).
Известное предупреждение: Рекорды — подпись уровня в таблице обрезается на телефонах (так задумано в `.board`). Новые экраны добавляй в audit.js.

## Скриншоты
`tools/screens.sh <пресет…>` — телефон 360×780 и ПК 1280×800, печатает пути к PNG (потом посмотреть через Read). Пресеты:
welcome, welcome2, home, levels, story, records, achievements, settings, profiles, intro, game, game-time, game-enemies, game-dark, game-story, pause, result, lose.
Ключи: `-m` только телефон, `-d` только ПК, `-j "<js>" имя` — свой сценарий; переменные AGE, HERO, MODE, LEVEL, OUT; HD=1 — снимок 2x.
Смотри не больше, чем нужно: 1–2 снимка затронутого экрана; широкий прогон по всем экранам — через агента `ui-check`.

Низкий уровень: `tools/shot.sh out.png ширина высота "<js>" задержка` (бинарник tools/.snap собирается из tools/snap.swift).
- Окно вне экрана система «замораживает» — скрипт отключает CSS-анимации и подменяет rAF; музыка выключена.
- Хранилище не сохраняется между запусками: каждый снимок начинается с чистого профиля (поэтому в screens.sh есть сид).
- Сервер на :8765 скрипты поднимают сами (tools/_server.sh). Без сервера snap висит 110 с и пишет «timeout».
- Ошибка на странице видна строкой `PAGE ERROR` (страница открывается с `?debug`).
- Системная тема на этом Mac тёмная — снимки получаются в тёмной теме; светлая: `-j "MZ.progress.setSetting('theme','light');MZ.app.applySettings();MZ.ui.show('home')"`.

## Грабли
- В zsh `trap … EXIT` внутри функции срабатывает при выходе из функции — фоновые процессы поднимай кодом на уровне файла (см. tools/_server.sh).
- `cmd | tail` в sh теряет код возврата `cmd` — в tests/run.sh вывод смоука сначала сохраняется в переменную.
- Правка генерации уровней меняет все сидированные уровни — перепроверь 812 уровней и автопилот.
- Service worker кэширует файлы по имени кэша с версией: после изменения списка файлов обнови ASSETS и версию.
