# Игровая механика: движение, управление, правила, сторожа, оценки

Источники: src/core/game.js, src/scenes/GameScene.js

Логика уровня — класс `Game` (src/core/game.js): чистый JS без Phaser, тестируется в Node. Всё, что надо показать или озвучить, он сообщает
событиями `emit()`; сцена `GameScene` только рисует и передаёт ввод. Правила игры в сцену не переносить.

## Движение
Герой всегда стоит в клетке или идёт между двумя соседними (`player.from → player.to`, прогресс `t` 0…1; `px`, `py` — положение в клетках).
`update()`: бюджет пути за кадр = `dt × level.speed`; цикл (до 6 клеток за кадр): если не идёт — `chooseStep()` → `startMove()`;
при `t ≥ 1` — `arrive()`. Логика стоит, пока `paused | won | lost | !started`. Первое действие игрока вызывает `begin()` → событие `start`.

**Движение только пошаговое** (требование пользователя): `chooseStep()` берёт направление из очереди нажатий `stepQueue` (≤ 3; непроходимый шаг
очищает очередь и даёт `bump()`), затем — повтор при удержании: `heldDir` после `holdDelay` секунд, строго по прямой, без автоповоротов.

API ввода у `Game`: `push()` (один шаг), `setHeld()` (удержание и задержка повтора), `release()`, `tapToward()` (шаг в сторону точки).

## Управление — `bindInput()` в GameScene
Одна схема на все устройства, без режимов:
| Жест | Действие |
|---|---|
| Свайп в любом месте (порог `SWIPE` = 14 CSS px, «плавающий якорь») | `push()` + `setHeld()`: один шаг; если палец не отпустить — через `HOLD_TOUCH` герой идёт дальше |
| Смена направления, не отрывая пальца | новый шаг сразу и повтор почти без задержки (0,1 с) — работает как джойстик |
| Короткий тап (< 400 мс, без сдвига) | `tapToward()` — шаг в сторону касания относительно героя |
| Стрелки / WASD, экранные стрелки (настройка `dpad`) | `pressDir()`: шаг и повтор через `HOLD_KEYS`; `e.repeat` игнорируется |
Две клавиши сразу: стек `held` — после отпускания одной герой идёт в сторону оставшейся. Второй палец во время свайпа игнорируется.
Ввод с кнопок HUD до игровой сцены не доходит: Phaser отдаёт касание только верхней сцене, если она его обработала.

## Проход, двери, ключи, выход
`passable(i, d)`: стена открыта И (нет двери ИЛИ дверь открыта ИЛИ есть ключ её цвета) И (сосед — не выход ИЛИ выход открыт).
Дверь открывается в `startMove()` → `openGate()`: ключ расходуется, событие `gateOpen`.
`bump()` (не чаще раза в 0,45 с): событие `bump`; если упёрлись в дверь — ещё `gateLocked`, в закрытый выход — `exitLocked`.
Выход («домик») открывается, когда собраны все обязательные находки (`remaining === 0`) → `exitOpen`. Победа — приход в клетку выхода.

`arrive()`: шаг++, событие `step`, подбор предмета `take()`, подбор ключа, победа, телепорт `teleport()` (защита от зацикливания —
`justTeleported`). `lastProgress` обновляется при новой клетке, предмете, ключе — на нём держится событие `stuck`.

## Предметы — `take()`
- `item` — обязательная находка мира: `remaining--`, событие `collect { got, total, left }`.
- `firefly` (ночные уровни): `lightRadius` +0,45, максимум 3,4. `heart` (много сторожей): +1 жизнь, максимум `maxHearts + 2`. Событие `bonus`.

## Подсказка — `useHint()`
BFS по проходимым сейчас рёбрам; цели: несобранные находки, невзятые ключи, двери, к которым уже есть ключ, открытый выход — берётся ближайшая.
Путь обрезается до `level.hintLen` клеток, живёт 7 с. Запас — `level.hints` (3 на уровень). Нет запаса → `noHints`.
Каждая подсказка снижает звёзды (см. ниже). Если 20 с нет прогресса — событие `stuck`, кнопка подсказки подмигивает.

## Сторожа — `updateEnemies()`, `enemyNext()`
- `patrol` — ходит по `route` туда-обратно; `wander` — случайно, старается не разворачиваться; `chaser` — идёт по градиенту `chaseField`
  к игроку, если расстояние ≤ `level.chaseRange` и игрок не в безопасной зоне (догоняющий подкрашен красным).
- Не заходят: в выход, в порталы, в безопасную зону у старта (`startDist < 3`), сквозь закрытые двери.
- Сон: цикл `level.sleep = [бодрствует от, до, спит]` секунд; спящий безопасен и неподвижен. Первый сон → `enemySleep`.
  **Сон обязателен**: без него патруль в единственном коридоре делал уровень непроходимым.
- Столкновение (расстояние² < 0,36, нет неуязвимости) → `onHit()`: −1 жизнь, неуязвимость 2,2 с, оглушение 0,35 с; 0 жизней → `lose()`.
  Жизней на уровне со сторожами — 3. Проиграть можно только на таких уровнях.
- Случайность сторожей берётся из `opts.random` конструктора (в тестах — сидированная).

## Ночь
`rules.dark`: видно только круг радиуса `lightRadius` клеток вокруг героя (рисует `placeFog()`), камера всегда близко.

## Итоги
`win()` и `lose()` только шлют события с `result()`; задержки и экран итогов — в `finish()` игровой сцены.

Звёзды — `computeStars()`: по отношению `steps / optimalSteps` к порогам `level.stars` (ночью пороги ×1,25, со сторожами ×1,3);
со сторожами — не больше `3 − столкновения`; одна подсказка → максимум 2 звезды, больше двух → максимум 1. Меньше одной звезды не бывает.
Очков нет: результат уровня — звёзды, шаги и время.
