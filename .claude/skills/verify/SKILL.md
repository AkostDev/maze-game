# Проверка изменений

Цель — убедиться, что правка ничего не сломала, потратив минимум контекста. Скрипты печатают по строке на этап; подробности только при ошибке.

1. Определи, что менялось:
   - только логика и данные (`src/core`, `src/gfx/sprites.js`, `src/gfx/mazeLayer.js`) → `tools/verify.sh`
   - сцены, интерфейс, камера, ввод, текстуры, звук, `index.html`, `sw.js` → `tools/verify.sh ui` (плюс смоук в браузере, ~45 с)
2. Если был затронут внешний вид — сними **только затронутые** экраны и посмотри их (`Read` по напечатанным путям):
   `node tools/screens.mjs <пресет…>` (пресеты и ключи — в `docs/kb/testing.md`; свой сценарий: `--js "<код>" имя`).
   По умолчанию — телефон стоя и ПК; раскладка зависит от ориентации, поэтому для экранов с кнопками добавь `-l` (телефон лёжа).
   Смотри: текст помещается и читается, ничего не налезает, цели касания крупные, пиксели ровные (нет размытия), HUD не закрывает лабиринт.
   Если экранов много (переделка набора интерфейса, новая раскладка) — поручи агенту `ui-check`.
3. Ошибка в тестах → исправь причину и запусти снова. Не подгоняй тесты под баг; несколько поражений автопилота на уровнях со сторожами — норма,
   застревание — нет. Смоук находит кнопки по имени: переименовал подпись — поправь сценарий `test/browser.smoke.mjs`.
4. `kb:` не ok → обнови затронутые документы `docs/kb/` и выполни `python3 tools/kb.py stamp` (подробно — скилл `kb-sync`).
5. В ответе пользователю — одна-две строки по факту: что запускалось и результат (например «тесты ok, браузер ok на телефоне и ПК, снимки меню посмотрел»).
   Если что-то не проверено (например, реальные устройства) — скажи прямо.
