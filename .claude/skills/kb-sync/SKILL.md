# Сверка базы знаний

База знаний — то, что читает следующая сессия вместо кода. Устаревшая база хуже, чем её отсутствие, поэтому сверка — часть каждой задачи.

1. `python3 tools/kb.py check` — покажет:
   - **битые ссылки** (в документе упомянуты функция, константа, CSS-класс, id или файл, которых больше нет) — исправь документ;
   - **что изменилось в коде** после прошлой сверки: файл, список символов (`~` изменён, `+` добавлен, `−` удалён) и документы, которые на него опираются.
2. Для каждого затронутого документа реши, изменилось ли то, что в нём **написано** (поведение, порядок вызовов, поля данных, числа, правила, рецепты).
   - Правил сам в этой сессии — ты знаешь, что поменялось; код перечитывать не нужно.
   - Изменения внесены вне сессии — прочитай только перечисленные символы (диапазоны строк в `docs/kb/MAP.md`).
   - Чистый рефакторинг без смены поведения документов не требует.
3. Правь точечно. В базу идёт то, чего не видно из карты кода: связи между модулями, инварианты, причины решений, «куда лезть», грабли.
   Не пиши номера строк (они в карте), не пересказывай код, не веди журнал изменений (для него `docs/PLAN.md`).
   Обозначения, которые проверяет линтер: функции — с пустыми скобками в бэктиках (как `startLevel()`), константы — `ИМЯ_ЗАГЛАВНЫМИ`, классы — `.имя`, id — `#имя`, файлы — путь.
4. Новая возможность, которую будут расширять, — добавь рецепт в `docs/kb/recipes.md`. Наступил на грабли — строка в «Грабли» в `docs/kb/testing.md`.
   Новый документ — файл в `docs/kb/` со строкой `Источники: …` под заголовком и строка в таблице-маршрутизаторе `CLAUDE.md`.
5. Изменились ключевые решения, статус или версия — обнови `CLAUDE.md` и `docs/PLAN.md`.
6. `python3 tools/kb.py stamp` — пометить базу сверенной. Затем `python3 tools/kb.py check` должен ответить `kb: ok`.

Карта `docs/kb/MAP.md` генерируется сама (хук после правок, а также `check` и `stamp`) — руками её не трогать. Новые реестры имён добавляются
в список `REGISTRIES` в `tools/kb.py`.
