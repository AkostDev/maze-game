# Волшебный клубок — пиксельная игра-лабиринт на Phaser 4

Браузерная игра «пройди лабиринт» для детей от 3 лет и взрослых: одна кампания из 50 уровней, сложность растёт постепенно.
Стек: **Phaser 4.2.1 (WebGL) + ES-модули, без сборки**; графика — пиксель-арт, который рисуется из данных в коде; язык интерфейса — русский.
Играть: https://akostdev.github.io/maze-game/ (GitHub Pages). Локально: `npm start` → http://localhost:8080 (ES-модулям нужен сервер;
двойной клик по `index.html` не работает). PWA, играет офлайн.
Главные устройства — смартфоны и планшеты (стоя и лёжа), ПК — тоже.

## Как работать с проектом (экономно — это требование пользователя)
Пользователь начинает новый чат под каждую идею. **Не перечитывай исходники целиком** — в проекте есть база знаний `docs/kb/`.

1. **Карта кода** подгружена в конце этого файла (`docs/kb/MAP.md`): все функции с диапазонами строк, реестры имён
   (спрайты, иконки, звуки, события, сцены, настройки…). Генерируется автоматически хуком после каждой правки.
2. **Открой 1–2 документа по задаче** (таблица ниже), а не код «на всякий случай».
3. **Читай код точечно**: `Read` с `offset`/`limit` по диапазону из карты, `Grep` для поиска. Файл `vendor/phaser.esm.min.js` не читать.
4. **API движка — из скиллов `phaser-*`** (официальная документация Phaser 4 в `.claude/skills`), а не по памяти: в четвёрке многое изменилось.
   Какой скилл под какую задачу — `docs/kb/phaser.md`.
5. **Проверка одной командой** (вывод в несколько строк): `tools/verify.sh` — логика; `tools/verify.sh ui` — плюс смоук всех сцен в браузере.
   После правок интерфейса и графики ещё снимки: `node tools/screens.mjs <пресет>` (телефон 360 px и ПК 1280 px; `-l` — телефон лёжа, `-t` — планшет).
6. **Обнови базу знаний** в том же ходе: поправь документы, чьё содержание изменилось (поведение, структуры данных, новые рецепты/грабли),
   затем `python3 tools/kb.py stamp`. Хук Stop напомнит, если код разошёлся с базой; SessionStart сообщит, что изменилось вне сессии.
   Писать в базу только то, чего не видно из карты: связи, инварианты, причины решений, «куда лезть». Номера строк в документы не писать.
7. **Git**: коммиты — только в ветку `main` (требование пользователя), без веток и pull request. Перед коммитом кода — `tools/verify.sh`.
   **`git push origin main` = публикация**: GitHub Pages раздаёт ветку `main` как есть, игроки получают изменения через минуту.
   Поэтому пушить только проверенное (`tools/verify.sh ui`) и когда пользователь просит опубликовать; после — `node tools/live.mjs --wait`.

Не заводи субагентов для чтения кода — база знаний дешевле. Агент `ui-check` (Sonnet) — только для широкой визуальной проверки многих экранов.
Скиллы проекта: `/verify` (проверка), `/screens` (снимки экранов), `/kb-sync` (сверка базы знаний).

## Архитектура в одном абзаце
ES-модули в `src/`. **`src/core/` — чистая логика без Phaser и DOM** (тестируется в Node): `maze.js` (сетка с битмасками проходов N=1, E=2, S=4, W=8,
генераторы, BFS), `levels.js` (уровень из сида и кривая сложности), `game.js` (класс `Game`: правила уровня, наружу — события),
`progress.js` (сохранение), `worlds.js` (данные миров и героев). `src/gfx/` — пиксель-арт как данные (`sprites.js`), сборка текстур (`textures.js`)
и картинка лабиринта (`mazeLayer.js`). `src/audio/sfx.js` — синтез звука. `src/ui/kit.js` — кнопки, панели, текст, метрики экрана.
**`src/scenes/` — сцены Phaser**: Boot → Menu ⇄ Levels / Settings → Game, поверх неё Hud, Pause, Result. `src/main.js` создаёт игру.
`GameScene` только показывает состояние `Game` и передаёт ему ввод; правила игры в сцены не переносить.

## Ключевые решения (не ломать)
- **Одна кампания, без возрастов и режимов** (требование пользователя): 5 миров × 10 уровней, затем бесконечный режим. Сложность растёт плавно;
  механики подключаются по одной (`UNLOCKS`): двери → фигуры → порталы → сторожа → ночь → догоняющие. На уровне-знакомстве — карточка с объяснением.
- **Управление — одна простая схема** (требование пользователя): свайп = шаг, не отпуская палец — герой идёт дальше, тап — шаг в сторону касания;
  стрелки/WASD; экранные стрелки — опция. Движение пошаговое, без «бега до развилки» и без автоповоротов.
- **Решаемость по построению**: двери — на рёбрах пути старт→выход идеального лабиринта (мосты), ключ k — в регионе до двери k, петли — только
  внутри региона, порталы — только в тупиках. Проверяется на 210 уровнях.
- Уровень детерминирован от сида `v2|индекс`; пропорции подстраиваются под экран. Правка генерации меняет все существующие уровни.
- Сторожа засыпают по циклу, спящие безопасны — иначе патруль в единственном коридоре делал уровень непроходимым. Проиграть можно только сторожам.
- **Пиксель-арт**: спрайты 16×16 — ASCII-карты с общей палитрой, клетка лабиринта 20 px (16 пол + 4 стена). Холст — в пикселях устройства,
  масштаб камеры и единица интерфейса `u` — целые числа: пиксели всегда ровные. Шрифт Tiny5 — кеглем, кратным 8 px.
- Без сборки и без файлов-ассетов (кроме шрифта): движок лежит в `vendor/`, картинки и звук синтезируются при загрузке.
- Хранилище: `klubok.v2` (один прогресс, без профилей); чужие и битые данные дают чистый прогресс, а не падение.

## Дизайн (подробно — docs/kb/ui.md)
Mobile-first; раскладки для телефона стоя и лёжа, планшета и ПК — каждая сцена перестраивается при повороте. Кнопки ≥ 46 CSS px.
Минимум текста: действия — иконкой и цветом (зелёная кнопка — «вперёд»). Фирменная деталь — «стежок» (пунктир по краю панели) и нить клубка,
которую герой разматывает за собой. Акценты: красный #ff5b4f, солнечный #ffcd45, зелёный #5fd068, бирюзовый #2ab8a8, виноградный #8b6cf6.

## Безопасность
Репозиторий публичный, и сайт раздаёт все его файлы — секретам в нём не место. В коде версии 2.0 секретов и обращений к сети нет.
Локальный файл js/config.js (ключ ИИ версии 1.1) исключён через .gitignore — не добавлять его в репозиторий и не копировать ключ
в документы, тесты и логи. Коммиты подписаны именем и адресом, которые заданы в локальной настройке git этого репозитория, — не менять их.
